## 3. 架构思路：为什么是「2 → 16 → 1」？

### 3.1 双月为什么必须有隐藏层

`make_moons` 的两个类别是两条互相咬合的半月。任何一条**直线**都无法把蓝红分开——用逻辑回归最多只能做到约 88%。所以单层感知机（`Linear(2→1)`，不管后面接什么都没用，因为"sigmoid 是单调函数，决策边界仍是一条直线"）在这里必然欠拟合。

### 3.2 ReLU 隐藏层的几何意义（关键直觉）

每个隐藏神经元只做一件事：

```
z = w1*x1 + w2*x2 + b        在 2 维平面上，这定义一条直线。
a = max(0, z)  ← ReLU        把平面折成两半：正侧线性上升，负侧压成 0
```

所以 **h 个隐藏神经元 = 在平面上画 h 条直线，把空间切成最多 h+1 个线性区域**。输出层再把这些区域加权求和，决策边界就变成一条**分段直线**（折线）。

- 半月轮廓是**弯曲**的 → 折线要足够多段才能贴合
- h 越大 → 可用的折线段越多 → 越能逼近曲线

我用你的数据独立跑了一遍（`_verify_capacity.py`，5 个随机种子）：

| 隐藏宽度 h | 测试准确率（均值±标准差） |
|---|---|
| 1 | 0.8260 ± 0.1630 |
| 2 | 0.8270 ± 0.1635 |
| 3 | 0.9110 ± 0.0256 |
| 4 | 0.9210 ± 0.0156 |
| 8 | 0.9970 ± 0.0060 |
| 16 | 0.9990 ± 0.0020 |
| 64 | 1.0000 ± 0.0000 |

**三个值得注意的现象**：

1. **容量确实随宽度单调增长**，而且 **h=8 就已经接近天花板**（你的 notebook 选 16 是合理的，留了余量）。
2. **h=1 和 h=2 的方差极大**（±0.16）。个别种子里直接掉到 **0.50**——也就是完全没学会、退化成随机猜测。这正是**欠拟合 + 初始化运气**的典型表现，不是"模型不够聪明"，而是"只有 1~2 个神经元时，梯度很容易把神经元推死"。
3. **你 notebook 里 B 实验（2 个神经元）报的 0.9250 是单次运气好的结果**。5 个种子平均只有 0.827。单次实验报数在这里是不可靠的——这解释了为什么 A(0.92) 和 B(0.925) 看起来"没差别"。

> 补充：Part 2 里"XOR 最少需要 1 个隐藏层、2 个神经元"是**表达能力**上的结论（存在一组能解的参数），不等于"2 个神经元训练一定能收敛"。A/B 两组的不稳定正说明了这个区别。

### 3.3 为什么输出层只给 logits（去掉 Sigmoid）

你 notebook 的做法是**正确且专业**的：

- `Sigmoid` + `BCE` 分开算，会在 `z` 很负时计算 `log(sigmoid(z))`，容易下溢成 `log(0) = -inf`
- `BCEWithLogitsLoss` 内部用 log-sum-exp 等价形式，数值稳定
- 数学上**完全等价**，表达能力没有任何损失

需要概率时手动 `torch.sigmoid(logits)` 即可。这个"**不要在网络里写 Softmax/Sigmoid 输出，交给损失函数**"是工业界的标准写法。

### 3.4 为什么用 Adam 而不是 SGD

双月只有 2 维、65 个参数，Adam 的自适应步长让它对学习率不敏感（0.01 就能收敛），几乎不用调。代价是**你可能因此学不到"学习率怎么调"**——这也是为什么你 notebook 的 E 实验（SGD lr=0.05）有价值。

### 3.5 完整架构模板（可以背下来）

```
输入层     : 直接接数据，不算一层
隐藏层 × N : Linear(d_in, d_h) → ReLU  [+ Dropout] [+ BatchNorm]
输出层     : Linear(d_h, d_out)
             二分类 → d_out=1，配 BCEWithLogitsLoss
             多分类 → d_out=K，配 CrossEntropyLoss（内部含 Softmax）
             回归   → d_out=1，配 MSELoss
```

## 5. 训练循环逐行精讲（这份代码最该学会的部分）

```python
for epoch in range(num_epochs):
    model.train()                        # ① 开启训练模式（Dropout 生效）
    perm = torch.randperm(n)             # ② 每 epoch 重新打乱，避免固定顺序
    for i in range(0, n, batch_size):
        idx = perm[i:i + batch_size]
        xb, yb = X_train[idx], y_train[idx]

        optimizer.zero_grad()            # ③ 清空上一轮梯度（忘了就累加！）
        logits = model(xb)               # ④ 前向
        loss = criterion(logits, yb)      # ⑤ 算损失
        loss.backward()                  # ⑥ 反向：算出所有参数的 .grad
        optimizer.step()                 # ⑦ 用 .grad 更新参数

    train_loss, train_acc = evaluate(model, X_train, y_train, criterion)  # ⑧
    test_loss,  test_acc  = evaluate(model, X_test,  y_test,  criterion)
```

**几个必须想清楚的点**：

1. **为什么评估要放在 epoch 结束、而不是 batch 里？**
   单个 batch 的 loss 噪声很大（64 个样本），曲线会剧烈抖动，看不出趋势。每个 epoch 在**全量数据**上评估一次，才是稳定信号。

2. **`evaluate` 里为什么必须有 `eval()` + `no_grad()`？**
   - `eval()`：关掉 Dropout/Dropout 类随机性，否则每次评估结果都不一致
   - `no_grad()`：不建计算图，省内存、提速（评估不需要梯度）

3. **`zero_grad()` 为什么在 batch 循环内部？**
   每个 batch 是独立的一次参数更新，必须在算新梯度前清掉旧的。放到循环外就会**梯度累加**——这是新手最常见的隐性 bug，模型不会报错，只是学得莫名其妙地差。

4. **最优权重为什么要 `deepcopy`？**
   `state_dict()` 返回的是**引用**，不深拷贝的话，后续训练会继续改这些张量，你保存的"最优模型"会跟着变。`copy.deepcopy` 才真正冻结那一刻。

5. **1000 样本 / batch 64 → 每 epoch 12 个完整 batch + 1 个 32 样本的尾批**。所以实际每 epoch 是 13 次参数更新，300 epoch ≈ 3900 次更新。理解这个数，才能估算训练时间（notebook 里实测 1.1 秒）。

## 6. 【重要】这份 notebook 的三处问题（我独立复现验证过）

### 问题 1：结论 4「标准化是必要的」不成立 —— 实验设计有缺陷

notebook 的 F 实验显示"不标准化"也是 `测试 acc 1.0000`，与基准**完全相同**，但结论 4 却写"对比实验 F 也说明了这一点（标准化的必要性）"。**实验和结论自相矛盾。**

我复现了实验 C vs F，各跑 10 个随机种子：

| 隐藏层 | 标准化 | 不标准化 |
|---|---|---|
| (16,) | 1.0000 ± 0.0000 | **0.9995 ± 0.0015** |
| (2,) | 0.9165 ± 0.0176 | 0.9160 ± 0.0148 |
| (64,64) | 0.9925 ± 0.0025 | 0.9910 ± 0.0139 |

**差距在噪声范围内，标准化在双月数据上几乎没有作用。** 原因很直白：

```
make_moons 原始特征：特征1 std=0.879，特征2 std=0.514   ← 尺度本来就接近！
```

两个特征尺度只差 1.7 倍，既没有量纲鸿沟，也不影响 Adam 的条件数。**标准化在这里不是"必要"，只是"无害的好习惯"。**

那标准化什么时候才真正起作用？我把数据人为拉开尺度再测：

| 特征尺度 | 标准化后 | 不标准化 |
|---|---|---|
| ×100 / ×1 | 1.0000 | 0.9890 |
| ×1 / ×100 | 1.0000 | 0.9810 |
| ×0.01 / ×1 | 1.0000 | **0.8740** |

**结论**：标准化在**特征尺度差 100 倍以上**时才明显必需。你未来处理真实表格数据（比如"年龄 0~100"和"收入 0~1000000"）时，它才从"好习惯"变成"不做就崩"。

**给你的一句话**：`StandardScaler` 要补上是对的，但理由应该是"为真实数据做准备"，而不是"双月数据必须要它"——后者是没有被实验支持的说法。

### 问题 2：对比实验在"饱和任务"上做，测不出差异

注意实验 C/D/E/F 的四组结果**全都是测试 acc 1.0000**，只有 A/B 明显更差。也就是说：

> 这个任务对 16 个以上的隐藏神经元来说**太简单了**，基准模型第 36 个 epoch 就到 100%，之后 264 个 epoch 全是"无差别"。在饱和的基准上比较，任何改进都测不出效果。

所以在双月上做"标准化有没有用""Dropout 有没有用""Adam 还是 SGD"这类实验，**几乎注定得到"没差别"的结论**——不是这些技术无效，而是**这个任务没有留出可改进的空间**。

**正确做法**（这才是"会做实验"的表现）：
- 想验证某项技术，先**把基准削弱到"能展现问题"的状态**：降低宽度（h=2）、加噪声（noise=0.30）、减少样本（n=100）
- 或者换一个**基准做不到 100%** 的任务（比如真实数据的 MNIST 子集、加噪正弦分类）
- 每组实验**跑多个随机种子报均值±标准差**，别只报一次

顺便：notebook 里 A(0.92) 和 B(0.925) 相差 0.005，**在单种子下完全是噪声**。我 5 种子的实测是 A≈0.826、B≈0.827（见 3.2 节）——两者其实都远低于 notebook 报的数，且都极不稳定。

### 问题 3：`run_experiment` 里有一个"侥幸没炸"的隐患

```python
if standardize:
    Xtr, Xte = X_train, X_test
else:   # 重新划分，拿一批没有标准化的数据
    Xall, yall = make_moons(...)
    Xtr, Xte, _, _ = train_test_split(Xall, yall, ...)   # ← 标签被丢掉了
...
hist, _, b_epoch, b_acc = train(m, Xtr_t, y_train_t, Xte_t, y_test_t, ...)  # ← 用的是全局标签
```

不标准化的分支里，**X 重新生成了，但 y 用的是全局 `y_train_t`/`y_test_t`**。这次没出错，纯属侥幸——因为 `make_moons(random_state=42)` 和 `train_test_split(random_state=42)` 是确定性的，同样的种子必然切出同样的顺序和标签。

**但只要改任何一个 `random_state`，X 和 y 就会错位，模型会学到"随机标签"**，而且**不会报错**，只是准确率莫名其妙地掉。这是个典型的"沉默 bug"。

修法：让函数内部同时返回配对的 X 和 y，别从外部闭包抓变量。

## 7. 关于"这是 AI 写的"——你该怎么用它

这份 notebook 质量不低（结构清晰、数值稳定写法正确、有对比实验意识），但上面三处问题说明了一个共同规律：

> **AI 生成的代码，"能跑通"和"结论正确"是两件事。**

它最典型的失效模式是：**代码跑出了数字，然后写一句漂亮的结论，但结论并没有被这些数字支持。**
问题 1 就是标本——数据说"没差别"，结论文本说"说明了必要性"。

**正确的使用姿势**：
1. **逐行追问**："这一行为什么存在？删了会怎样？"——比如把 `scaler` 那两行注释掉，自己看结果变不变。
2. **复现每个结论**：凡是文档里写着"这说明了 X"的地方，都自己跑一遍。复现不出来的，标为"待验证"。
3. **多随机种子**：单次结果只能当"跑通了"的证据，不能当"更优"的证据。
4. **注意"沉默 bug"**：不会报错但结果错的地方（形状广播、变量错位、忘了 `zero_grad`）才是真正的时间黑洞。

这正是你上一轮说的"样板答案"问题的解法：**不是不借助 AI，而是把 AI 的输出当作待验证的假设。**
