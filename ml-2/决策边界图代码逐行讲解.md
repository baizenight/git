# 决策边界图代码逐行讲解（初学者版）

> 这份文档讲解的是下面这段代码：在二维特征平面上，把神经网络对每个位置的预测结果画成颜色，再叠加上真实数据点，从而"看见"模型学到的决策边界。

---

## 一、读之前先知道三件事

在看代码之前，先明确三个前提，后面的解释都建立在这上面：

1. **`X_train` 是一个 PyTorch 张量（tensor），形状是 `(800, 2)`。**
   800 表示 800 个样本，2 表示每个样本有 2 个特征（可以理解为平面上的 x 坐标和 y 坐标）。

2. **`model` 是一个多层感知机（MLP），最后一层是 `Sigmoid`。**
   所以 `model(输入)` 的输出是**概率**：即 P(y=1)，取值范围是 0 到 1。
   - 输出接近 1 → 模型认为这个点属于"正类"
   - 输出接近 0 → 模型认为这个点属于"负类"
   - 输出正好 0.5 → 模型"拿不定主意"，这条线就是决策边界

3. **"决策边界图"要表达什么？**
   我们想知道：**平面上每一个位置，模型都会预测成哪一类？**
   但模型只能对"具体的数据点"做预测。所以我们的办法是：
   **自己造一大堆密密麻麻的假坐标点，铺满整个平面，让模型一个个预测，再把预测结果用颜色画出来。**

   这段代码做的所有事情，本质上就是这一件事。

---

## 二、完整代码

```python
import numpy as np

x_min, x_max = X_train[:, 0].min().item(), X_train[:, 0].max().item()
y_min, y_max = X_train[:, 1].min().item(), X_train[:, 1].max().item()
pad = 0.5                                        # 留白，别让点贴边

xx, yy = np.meshgrid(np.linspace(x_min - pad, x_max + pad, 300),
                     np.linspace(y_min - pad, y_max + pad, 300))
grid = torch.as_tensor(np.c_[xx.ravel(), yy.ravel()], dtype=torch.float32)

model.eval()
with torch.no_grad():
    zz = model(grid).numpy().reshape(xx.shape)   # 概率面

plt.figure(figsize=(7, 6))
plt.contourf(xx, yy, zz, levels=20, cmap="RdYlBu_r", alpha=0.7)
plt.contour(xx, yy, zz, levels=[0.5], colors="k", linewidths=1.5)

tr_x, tr_y = X_train.numpy(), y_train.numpy().ravel()
te_x, te_y = X_test.numpy(),  y_test.numpy().ravel()
plt.scatter(tr_x[:, 0], tr_x[:, 1], c=tr_y, cmap="RdYlBu_r",
            edgecolors="k", s=25, marker="o", label="Train")
plt.scatter(te_x[:, 0], te_x[:, 1], c=te_y, cmap="RdYlBu_r",
            edgecolors="w", s=40, marker="^", label="Test")
plt.xlabel("Feature 1"); plt.ylabel("Feature 2")
plt.title("Decision Boundary (MLP, hidden=16)")
plt.legend(); plt.colorbar(label="P(y=1)")
plt.show()
```

先记住整体的四步流程，再看细节就不容易迷路：

```
第 1 步（第 2~8 行）：量出数据占多大地方，往外扩一圈
第 2 步（第 5~9 行）：在这块地方铺满密密麻麻的坐标点（网格）
第 3 步（第 10~12 行）：让模型预测每个网格点的概率
第 4 步（第 14~24 行）：把概率画成颜色，把真实数据点画成散点
```

## 三、逐行讲解

### 第 1 行：`import numpy as np`

导入 numpy，后面要用来生成网格坐标。

前面的代码里只导入过 `torch`、`sklearn` 和 matplotlib 的 `plt`，numpy 是画网格才第一次需要，所以这里单独导入。
`as np` 是给它起个短名字，之后写 `np.xxx` 就行。

---

### 第 3~4 行：量出第一个特征的范围

```python
x_min, x_max = X_train[:, 0].min().item(), X_train[:, 0].max().item()
```

拆开看，从里到外：

- `X_train[:, 0]`：取所有行的第 0 列，也就是**第一个特征**的全部数值。形状从 `(800, 2)` 变成 `(800,)`。
- `.min()` / `.max()`：求最小值和最大值。注意在 PyTorch 里，它们返回的不是普通数字，而是一个**0 维张量**。
- `.item()`：把 0 维张量取出成普通的 Python 浮点数（float）。

**为什么要 `.item()`？**
严格说不是必须的，`np.linspace` 也能接受 0 维张量。但显式转成 float 更干净，可以避免后面把张量混进 numpy 运算时出现奇怪的类型问题或报错。

**一个值得注意的设计选择：**
这里**只用训练集**来确定画布范围，而不是训练集 + 测试集一起。
理由是：如果用测试集的极值来定画布，等于"提前看了测试集"。
但代价是：如果测试集里有比训练集更靠边的点，可能会被图片边缘裁掉。如果你发现测试点被切掉了，可以改成对 `np.vstack([X_train, X_test])` 取范围。

---

### 第 5 行：量出第二个特征的范围

```python
y_min, y_max = X_train[:, 1].min().item(), X_train[:, 1].max().item()
```

和上一行完全同理，只是把第 0 列换成第 1 列，得到**第二个特征**的范围。

到这里，我们得到了数据在平面上占据的矩形区域：
`x` 从 `x_min` 到 `x_max`，`y` 从 `y_min` 到 `y_max`。

---

### 第 6 行：`pad = 0.5`

给矩形区域四周各**额外留出 0.5 的空白**。

**为什么需要留白？**
如果不留白，数据点会紧贴在图片的最边缘，看着很挤；更要命的是，角落处的决策边界会被图片边缘截断，图看起来不完整。加一圈留白之后，整个边界能完整展示出来。

---

### 第 7~8 行：铺网格

```python
xx, yy = np.meshgrid(np.linspace(x_min - pad, x_max + pad, 300),
                     np.linspace(y_min - pad, y_max + pad, 300))
```

这行是整段代码里最抽象的一句，慢慢来。

**第一步：`np.linspace(起点, 终点, 300)`**

在起点和终点之间，**等距离地取 300 个数字**。
例如 `np.linspace(0, 1, 5)` 得到 `[0, 0.25, 0.5, 0.75, 1]`。

所以：
- 第一个 `linspace` 在 x 方向上取 300 个均匀的横坐标
- 第二个 `linspace` 在 y 方向上取 300 个均匀的纵坐标

**第二步：`np.meshgrid(...)`**

它把"一条横线"和"一条竖线"**交叉成一张网**，返回两个都是 `(300, 300)` 的矩阵：

- `xx[i, j]`：第 i 行第 j 列那个格点的 **x 坐标**
- `yy[i, j]`：同一个格点的 **y 坐标**

你可以想象成用笔画一张 300×300 的方格纸，`xx` 记录每个格子的横坐标，`yy` 记录纵坐标。两者配合才能确定一个点。

**为什么是 300？**
分辨率。数字越大网格越密，画出来的边界越平滑，但计算也越慢。
- 300×300 = 90000 个点，对手写这么小的网络完全够快
- 100 左右会明显看到锯齿
- 500 以上基本看不出提升，只是白等

**⚠️ 一个隐藏的关键点：默认排序方式**

`np.meshgrid` 默认是 `indexing='xy'`，也就是：
- `xx` 沿着**列**的方向变化
- `yy` 沿着**行**的方向变化

这决定了后面 `.reshape()` 必须怎么写。如果这里写成 `indexing='ij'`，图像会整体错位（就像把图片旋转了 90°），后面的坑里还会再提。

---

### 第 9 行：把网格打包成模型能吃的输入

```python
grid = torch.as_tensor(np.c_[xx.ravel(), yy.ravel()], dtype=torch.float32)
```

这一行把 `(300, 300)` 的两张坐标表，变成 `(90000, 2)` 的模型输入。

从里到外拆解：

1. **`xx.ravel()`**：把 `(300, 300)` 的矩阵拉平成一维 `(90000,)`。
   `ravel` 是"按行优先"展开的，即先读第一行从左到右，再读第二行……
   **这个顺序非常重要**，后面 reshape 回去时必须用同样的顺序。

2. **`yy.ravel()`**：同理，把纵坐标也拉平。两个数组的第 k 个元素描述的是**同一个格点**。

3. **`np.c_[a, b]`**：按列拼接。
   把两个 `(90000,)` 拼成 `(90000, 2)`——每一行是一个格点的 `[x, y]`。
   这个形状正好就是模型期望的 `(batch_size, input_size)`。

4. **`torch.as_tensor(..., dtype=torch.float32)`**：转成 PyTorch 张量，并把数据类型指定为 32 位浮点，和模型参数的精度一致。

   **一个小知识点**：`np.c_` 默认产出 `float64`，而这里要求 `float32`，两者不同，所以**这一步会真正复制一份数据**。（如果类型相同，`as_tensor` 会和 numpy 数组共享内存，不复制。）

**这一步的实际含义：**
我们现在把 90000 个格子点排成一队，准备一次性喂给模型。这相当于一个 90000 样本的大 batch。对这个 2→16→1 的小网络来说，CPU 上瞬间就能算完。

---

### 第 11~12 行：让模型预测每个格点

```python
model.eval()
with torch.no_grad():
    zz = model(grid).numpy().reshape(xx.shape)   # 概率面
```

**第 11 行 `model.eval()`**：把模型切换到"推理模式"。

对你的这个网络来说，**这一行其实没有实际影响**，因为网络里没有 Dropout、没有 BatchNorm（这两类层在训练和推理时行为不同）。
但它是一个**标准习惯**：

- 现在就写上，将来往网络里加 Dropout 时不会因为忘记而踩坑
- 训练之后模型通常已经是 eval 状态了，再写一次也无害

**第 12 行 `with torch.no_grad():`**：关闭自动求导。

- **省内存、跑得快**：反向传播需要的中间结果不会被保存
- **让 `.numpy()` 能正常工作**：带梯度信息的张量调用 `.numpy()` 会报错
  （`RuntimeError: Can't call numpy() on Tensor that requires grad`）
- 等价写法是 `model(grid).detach().numpy()`

**`model(grid)`**：一次前向传播，输出形状是 `(90000, 1)`。
每个元素就是那个格点被模型判为"正类"的概率 P(y=1)。

**`.numpy()`**：把张量转回 numpy 数组，形状还是 `(90000, 1)`。

**`.reshape(xx.shape)`**：把 `(90000, 1)` 还原成 `(300, 300)`。

这是为了让 `zz[i, j]` 和 `xx[i, j]`、`yy[i, j]` 指向**同一个格点**。
因为 `ravel()` 时是按行优先，`reshape` 也是按行优先，所以顺序能严丝合缝地对上。

最后 `zz` 的含义：**一张 300×300 的"概率地图"，记录了平面上每个位置的预测概率。**

> ⚠️ **另外提醒**：`.numpy()` 要求张量在 CPU 上。如果你把模型放到 GPU 训练过，这里要先写 `.cpu()`，变成 `.cpu().numpy()`。

---

### 第 14 行：新建画布

```python
plt.figure(figsize=(7, 6))
```

新建一张 7×6 英寸的画布。

决策边界图接近正方形（而不是细长条形）看起来最自然。这里的 7 和 6 就是宽和高。

---

### 第 15 行：用颜色填充概率面

```python
plt.contourf(xx, yy, zz, levels=20, cmap="RdYlBu_r", alpha=0.7)
```

注意函数名结尾的 **`f`**，代表 **filled（填充）**。它会按 `zz` 的数值给平面上色。

逐个参数看：

- **`xx, yy, zz`**：三个 `(300, 300)` 的矩阵。`xx`/`yy` 告诉 matplotlib 每个颜色的位置，`zz` 告诉它每个位置用什么颜色。

- **`levels=20`**：把概率值从最小值到最大值**分成 20 个等距的层级**，每一层一个颜色。层数越多，颜色过渡越细腻，越能看出模型在哪一带"不确定"（颜色过渡的黄绿区间）；层数少则变成明显的色块。

- **`cmap="RdYlBu_r"`**：颜色映射方案（colormap）。`RdYlBu` 表示 红-黄-蓝；结尾的 **`_r` 是 reverse（反色）**。
  - 用自带反色是为了：**概率接近 1 → 显示偏红，概率接近 0 → 显示偏蓝**，符合直觉
  - 如果写成 `"RdYlBu"`（不带 `_r`），颜色就反过来了，很容易看错
  - 顺便一提，这不是经典的 `"RdBu"`，它中间会经过**黄色**，所以边界附近呈现黄绿色

- **`alpha=0.7`**：透明度，0 完全透明、1 完全不透明。
  **这个参数是为了后面叠上去的散点着想**——半透明的色块不会把数据点盖住。

> 如果你只想看"硬分类"（只分正负两片区域），可以把这一行换成：
> `plt.contourf(xx, yy, zz, levels=[0, 0.5, 1], colors=["#4C72B0", "#DD8452"])`
> 这样正负两类各一个纯色块，更简洁。

---

### 第 16 行：画出决策边界本身

```python
plt.contour(xx, yy, zz, levels=[0.5], colors="k", linewidths=1.5)
```

这一行不带 `f`，所以它**不填充颜色，只画等高线**。

- **`levels=[0.5]`**：只画"概率等于 0.5"的那一条线。
  这正是**决策边界**，因为模型判定规则是"概率 ≥ 0.5 就算正类"，所以 0.5 这一条线就是两类区域的分界。

- **`colors="k"`**：`k` 是 black 的缩写（matplotlib 沿用 MATLAB 的单字母颜色代码）。黑色线条在彩色背景上最醒目。

- **`linewidths=1.5`**：线宽。确认单位是磅（point），1.5 比默认的 1.0 略粗，让边界更清楚。

---

### 第 18~19 行：准备散点数据

```python
tr_x, tr_y = X_train.numpy(), y_train.numpy().ravel()
te_x, te_y = X_test.numpy(),  y_test.numpy().ravel()
```

- **`.numpy()`**：把训练集、测试集的张量转成 numpy 数组。
- **`.ravel()`**：`y_train` 的形状是 `(800, 1)`，压平成 `(800,)`。

**为什么标签一定要 ravel？**
`plt.scatter` 的 `c=` 参数（颜色）期望一维的数值序列。传二维的 `(800, 1)` 可能报错或触发形状警告，所以必须压平。

---

### 第 20~23 行：画训练集散点

```python
plt.scatter(tr_x[:, 0], tr_x[:, 1], c=tr_y, cmap="RdYlBu_r",
            edgecolors="k", s=25, marker="o", label="Train")
```

- **`tr_x[:, 0], tr_x[:, 1]`**：散点的横坐标和纵坐标。
- **`c=tr_y`**：**按真实标签给点上色**。标签只有 0 和 1 两个值，经 `cmap` 映射成两种颜色。
  关键点在于：散点和背景用的是**同一条色带**。所以"红点落在红色区域"就表示预测正确，一眼就能看出哪些点被分错了。
- **`edgecolors="k"`**：黑边。
  加描边是为了**让点从同色系的背景中分离出来**。否则一个红点落在红色区域里，几乎看不见。
- **`s=25`**：点的面积（磅²），这里算中等大小。
- **`marker="o"`**：圆形标记。
- **`label="Train"`**：给图例用的名字。没有它，后面的 `plt.legend()` 就是空的。

---

### 第 24~25 行：画测试集散点

```python
plt.scatter(te_x[:, 0], te_x[:, 1], c=te_y, cmap="RdYlBu_r",
            edgecolors="w", s=40, marker="^", label="Test")
```

和上一行几乎一样，只有四处不同，都是为了**和训练点区分开**：

| 参数 | 训练点 | 测试点 | 目的 |
| --- | --- | --- | --- |
| `edgecolors` | `"k"` 黑边 | `"w"` 白边 | 描边颜色不同 |
| `s` | 25 | 40 | 测试点稍大，更容易看清 |
| `marker` | `"o"` 圆 | `"^"` 三角 | 形状不同 |
| `label` | `"Train"` | `"Test"` | 图例名不同 |

**为什么测试点要更醒目？**
测试点数量少（200 个 vs 800 个），而且它们才反映泛化能力，值得看得更清楚。

plt.xlabel("Feature 1"); plt.ylabel("Feature 2")

### 第 28 行：图例和颜色条

```python
plt.legend(); plt.colorbar(label="P(y=1)")
```

- **`plt.legend()`**：显示图例，内容来自两个 scatter 的 `label` 参数（Train / Test）。
  它**不会**把 `contourf`/`contour` 加进去，因为填充色块不是"点/线"类型的图例项。所以图例里只有两项，这是正常的。

- **`plt.colorbar(label="P(y=1)")`**：在右侧加一条颜色条，说明"什么颜色对应什么概率"。

  有个小细节：默认情况下，colorbar 绑定到当前坐标轴上**最后一个"可映射对象"**，也就是第二个 scatter（而不是背景的 `contourf`）。
  因为两个 scatter 的取值和 `contourf` 的 `zz` 都在 0~1 之间、且用的是同一条 `cmap`，所以颜色条和背景**视觉上是一致的**，不用管它。

  如果你希望它严格跟随概率面，可以显式指定：

  ```python
  h = plt.contourf(xx, yy, zz, levels=20, cmap="RdYlBu_r", alpha=0.7)
  plt.colorbar(h, label="P(y=1)")
  ```

显示图像。在 Jupyter 的 inline 后端下会直接渲染到输出区。

**顺序提醒**：如果你还想保存图片，`plt.savefig(...)` 必须写在 `plt.show()` **之前**：

plt.savefig("decision_boundary.png", dpi=150, bbox_inches="tight")

## 四、整体回顾

把整段代码串成一句话：

> **先量出数据占多大地方 → 在这块地方铺一张 300×300 的坐标网格 → 让模型预测每个格点的 P(y=1) → 用半透明颜色把概率填出来、用黑色 0.5 等高线勾出决策边界 → 再把训练点和测试点按真实标签叠上去。**

最后看图的方法：

| 你看到的 | 说明 |
| --- | --- |
| 红点和蓝点大致被黑线分到两边 | 模型学得不错 |
| 有红点落在蓝色区域（或反过来） | 该点被分错了 |
| 背景颜色过黄色区域 | 模型在这里"不确定"（概率接近 0.5） |
| 训练点全对，但测试点错很多 | 过拟合 |

## 五、三个最容易踩的坑

### 坑 1：`reshape` 没写，或者和 `meshgrid` 的 indexing 不匹配

```python
zz = model(grid).numpy().reshape(xx.shape)   # ✅ 正确
zz = model(grid).numpy()                     # ❌ 形状是 (90000, 1)，画出来全乱
```

如果形状和 `xx`/`yy` 对不上，或者 `meshgrid` 用了 `indexing='ij'` 而 reshape 按默认方式，背景色块会和散点**整体错位**（像是被旋转了），看起来特别像"模型学歪了"，其实只是画图配对错了。

### 坑 2：`levels=[0.5]` 和 `contourf` 混用

`plt.contourf(..., levels=[0.5])` 只会画出寥寥几条填充带，甚至报错或什么都不显示。
记住分工：**`contourf` 负责填色（给十几个 levels），`contour` 负责画那一条边界线（只给 `[0.5]`）。**

### 坑 3：`cmap` 忘了加 `_r`

`"RdYlBu"` 和 `"RdYlBu_r"` 颜色完全相反。
如果忘了加 `_r`，就会出现"概率 1 是蓝色、概率 0 是红色"的情况，和散点的颜色对应关系反了，图看着就完全矛盾。

## 六、可选改动小抄

| 想做什么 | 怎么改 |
| --- | --- |
| 网格更平滑 | 把两个 `300` 改成 `500`（更慢） |
| 网格更快 | 改成 `150`（会有锯齿） |
| 想看清置信度渐变 | 保持 `levels=20` |
| 只想看硬分类 | `levels=[0, 0.5, 1], colors=[...]` |
| 白色背景不好看 | 用 `cmap="coolwarm"` 或 `"bwr"` |
| 边界线想画成白色 | `colors="w"` |
| 中文标签 | 先设 `plt.rcParams["font.sans-serif"] = ["SimHei"]` |
| 保存图片 | `plt.savefig("xxx.png", dpi=150, bbox_inches="tight")`，放在 `show()` 前 |
| 图上有点被裁掉 | 把 `pad` 从 `0.5` 调到 `1.0` |
